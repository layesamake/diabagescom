## Objectif

Construire l’application intégralement, dans l’ordre du backlog : socle sécurisé multi-entreprise, gestion commerciale, stock, PWA hors connexion, comptabilité SYSCOHADA et paiements SaaS.

## Règles non négociables

- Toute donnée métier est isolée par entreprise (`tenant_id`) et ce contrôle est exécuté côté serveur.
- Aucun montant financier n’utilise de nombre flottant ; tous les montants XOF sont stockés en entiers.
- Une facture validée, un mouvement de stock, un paiement, une écriture comptable postée ou une trace d’audit ne sont jamais modifiés ni supprimés directement.
- Toutes les mutations critiques sont transactionnelles, autorisées, auditables et idempotentes lorsqu’elles peuvent être rejouées.
- Ne jamais mettre de secret dans le dépôt, les logs, les images Docker ou le navigateur.
- L’interface est en français clair, tactile, responsive et utilisable par des non-informaticiens.
- La PWA hors connexion ne promet jamais une validation définitive avant synchronisation serveur.
- Toute règle comptable/fiscale finale nécessite validation d’un expert-comptable compétent avant production.

## Méthode de travail

1. Inspecter le dépôt, les instructions locales, l’état Git et les dépendances existantes.
2. Commencer exclusivement par `EPIC-00`, puis poursuivre séquentiellement dans `docs/14-backlog-implementation.md`.
3. Avant chaque fonctionnalité : définir migration/contraintes, autorisations, service métier transactionnel, tests, API, interface et audit.
4. Tester isolation inter-entreprises, permissions, idempotence, règles de stock et responsive mobile pour chaque module concerné.
5. Mettre à jour la documentation si une décision ou un contrat évolue.
6. Ne pas activer les paiements réels, clés de production ou modifications de production sans validation explicite du propriétaire.
